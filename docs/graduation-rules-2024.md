# 2024年度入学・知能情報コースの卒業要件判定設計

## 状態と対象

[Issue #23](https://github.com/ore-orange/graduation-requirements-checker/issues/23)の実装資料。一次資料由来の要件JSON・科目マスタ、実績・見込み判定、将来計画のDB保存をローカルデモ`/demo`で利用できる。

合意済みの対象は、琉球大学 工学部 工学科 知能情報コースの2024年度入学生。外国人学生の特例、編入・転学科に伴う個別認定等は今回の対象外。実績判定と見込み判定は区別する。

一次資料は利用者が用意した[kogaku_chinot_y24.pdf](kogaku_chinot_y24.pdf)。抽出テキストだけでは結合セル・括弧・下線を誤読するため、原本の画像でも確認した。

| 便覧の記載ページ | PDFのページ | 用途 |
| --- | --- | --- |
| 1 | 2 | 提供科目、科目番号、単位数、必修の○、工学融合の登録制限 |
| 10 | 11 | 卒業要件の数値、括弧の範囲、注1〜10 |
| 11 | 12 | 専門科目と分類の対応、工学共通科目の下線 |
| 12 | 13 | GEプログラムの科目リスト。卒業単位の条件とは分ける |
| 13 | 14 | 履修モデル。必修・選択の照合に使うが、モデルどおりの履修を強制しない |

以下は便覧の読み取り結果と現在の実装。原本で確定できない科目や組合せは確認理由を残し、架空の要件や単位で埋めない。実学生データ・教務連携・大学による最終認定の代替ではない。

## 1. 単位を数える前に適用する原則

- 修得単位数の合計と、卒業要件に算入できる単位数の合計を区別する。
- 同じ単位は区分の小計・上位の小計の両方に寄与してよいが、卒業算入総単位を求める際に二重加算しない。
- 必修科目は科目ごとの修得を確認する。区分内の別科目や、他区分の余剰単位で置き換えない。
- 科目名だけでは分類しない。技術英語Ⅰ・ICT実践英語Ⅰは専門科目であり、名前が英語でも共通教育の英語に移さない。
- 自然系の算入上限を超えた単位、情報科学演習などの算入不可科目を、最終的な130単位の計算に戻さない。

同一科目の再履修を履修記録の行数で重複加算しない。明示的な修得済み記録を将来計画より優先し、修得単位や必要な承認が競合した記録は要確認にする。複数回算入を認める制度・読み替え・同等科目の扱いに根拠がない場合は、科目番号や名称だけで確定しない。

## 2. 共通教育

出典：便覧10ページの共通教育の括弧と注1・注4。

### 2.1 健康運動、教養・総合領域

次の記号は、それぞれの区分に算入可能な単位数を表す。

- `H`：健康運動系
- `U`：人文系
- `S`：社会系
- `N`：自然系の修得単位
- `G`：総合科目＋キャリア関係科目＋琉大特色・地域創生科目
- `A = U + S + G`
- `B = A + min(N, 2)`

すべての条件を満たす必要がある。

| 条件 | 判定式 |
| --- | --- |
| 健康運動系 | `H >= 2` |
| 人文系 | `U >= 2` |
| 社会系 | `S >= 2` |
| 総合領域の3区分の合計 | `G >= 2` |
| 自然系を除いた指定範囲 | `A >= 12` |
| 人文・社会・自然・総合領域の合計 | `B >= 14` |

`B`に健康運動系は含めない。14単位は自然系だけの必要単位ではない。

`G >= 2`は3区分の合計条件であり、キャリア関係だけで2単位を必須にしたり、3区分それぞれ2単位を要求したりしない。

自然系の最低単位はこの表では指定されていない。自然系が0単位なら`A >= 14`が必要。自然系を何単位修得しても、卒業単位への算入は2単位まで。

### 2.2 日本語表現法入門

日本語表現法入門の修得を確認する（2単位）。任意の情報関係科目を2単位修得しただけでは代用しない。

注4の情報科学演習は、卒業要件の総単位数に含めない。

### 2.3 外国語の二経路

`E`を共通教育の英語の算入単位、`L[language]`を英語以外の特定の一外国語の算入単位とする。

まず、どちらの経路でも「大学英語」「英語講読演習中級」の修得が必要。そのうえで、次のいずれかを満たす。

```text
(E >= 8 AND いずれか一つの language について L[language] >= 4)
OR
(E >= 12)
```

例：英語8＋ドイツ語2＋中国語2は、一外国語4の条件を満たさない。英語12でも、指定英語科目の欠落は埋められない。

これは通常の選択経路であり、今回対象外にした外国人学生の日本語科目による読み替え特例とは異なる。

### 2.4 共通教育全体

上記の個別条件に加えて、共通教育の算入単位が30以上であることを確認する。

```text
共通教育 = H + B + 日本語表現法入門の算入単位 + 外国語の算入単位
共通教育 >= 30
```

科目別区分・言語・指定英語科目の詳細は、公式の[2024年度共通教育等授業科目表](https://rais.skr.u-ryukyu.ac.jp/wordpress/wp-content/uploads/binran/R6/01gakubu/01kyotsu/00-04kyotsu_jugyokamoku.pdf)と[講義内容](https://rais.skr.u-ryukyu.ac.jp/wordpress/wp-content/uploads/binran/R6/01gakubu/01kyotsu/00-05kyotsu_koginaiyo.pdf)で確認し、要件JSONへ登録した。大学英語（外101）は4単位、英語講読演習中級（外102）は2単位。

## 3. 専門基礎教育

出典：便覧10ページ「専門基礎教育」、13ページの履修モデル。

専門基礎6単位以上に加えて、次の指定科目の修得を確認する。

```text
((微分積分学STⅠ AND 微分積分学STⅡ)
 OR (微分積分学入門Ⅰ AND 微分積分学入門Ⅱ))
AND
(物理学Ⅰ OR 物理学入門Ⅰ)
```

STⅠ＋入門Ⅱのような系列を混在させる場合や、代替科目の両方を修得した場合の重複算入可否は、このPDFだけでは確定できない。上式は便覧に明示された組合せであり、混在を不成立と断定するための根拠ではない。そうした入力は追加確認が必要。

任意の専門基礎科目を6単位集めるだけの判定にはしない。

## 5. 専門選択：37単位の内数として22単位と工学融合4単位

出典：便覧10ページの内外の括弧、注3・注7・注9・注10、11ページの分類表。

| 記号 | 区分 | 対応 |
| --- | --- | --- |
| `M` | 数学基礎（選択） | 工業数学Ⅲ・Ⅳ、確率及び統計。工業数学Ⅰ・Ⅱ・離散数学は含めない |
| `V` | 知能情報アドバンスト | 11ページの該当区分に列挙された科目 |
| `R` | 知能情報関連 | 同分類表の該当科目。数学基礎などに分類された下線付き工学共通科目を再加算しない |
| `F[c]` | コース`c`が提供する工学融合 | 提供科目表の導入・選択科目。自コース提供分は登録不可 |
| `X` | 専門科目（自由） | 他コース・他学部等が提供する所定の専門科目。共通教育と専門基礎（先修）は除く |

すべての条件を満たす。

```text
M + V + R >= 22
sum(F[c]) + M + V + R + X >= 37
いずれか一つの他コース c について F[c] >= 4
```

- 22単位はアドバンスト単独ではなく、選択数学・アドバンスト・関連の合計。
- 工学融合と自由科目は37に入るが、22には入らない。
- 工学融合を機械2＋電気2のように分散しただけでは、同じコースから4の条件を満たさない。
- 1コースから4を満たしたうえで、他コースの算入可能な工学融合科目を追加することまで禁止する記載ではない。
- 他学部提供の情報系科目には指導教員の承認が必要。これは標準要件の注3にある条件であり、「特例除外」を理由に無条件算入しない。
- 全教412「教職実践演習（高）」は注10で知能情報関連への算入が明記されている。教職科目を一律に除外しない。ただし単位数等のマスタ情報は追加資料で確認する。

## 6. 総単位と条件の組合せ

```text
卒業算入総単位 = 共通教育 + 専門基礎 + 専門必修 + 専門選択
卒業算入総単位 >= 130

全体の充足 = 共通教育の全条件
           AND 専門基礎の指定科目・単位条件
           AND 専門必修の全科目修得
           AND 専門選択の22・37・同一コース4の全条件
           AND 総単位条件
```

最低構成の算術は`30 + 6 + 57 + 37 = 130`。22と4をさらに足さない。

各区分の最低値を上回る単位があっても、別の区分の不足や必修科目の欠落を埋めない。

これは当該PDFから読み取れる科目・単位要件の判定である。在学期間等を含む大学の最終的な卒業認定全体を、このPDFだけで網羅できるとは扱わない。

### 卒業単位とは分ける条件

注8の卒業研究Ⅰの登録要件は、卒業単位の充足条件とは別に保持する。

- 6個学期在学後は取得単位100以上。
- 5個学期在学後の4月は取得単位85以上。
- 原則として3年後学期までの専門必修科目をすべて修得。

取得単位の集計範囲を卒業算入単位と同一だと推測しない。登録可否をアプリの出力に含めるかは未合意。

12ページのGEプログラム科目リストを、全員の卒業必修へそのまま追加しない。GE修了判定の要否と制度全体の要件は未確認。

## 7. 実績判定と見込み判定の共通ロジック（実装済み）

1. 対象年度・コースと特例の有無を確認する。
2. 科目の同一性、年度別の分類、提供コース、算入可否を確定する。
3. 修得済み科目と履修予定科目を明示的に分ける。不合格や成績未確定を、予定科目と自動的に同一視しない。
4. 実績判定は修得済みの科目・実際の修得単位で評価する。
5. 見込み判定は修得済みに、予定科目を修得した仮定の単位を加え、同じ要件式で評価する。修得済みと重なる科目をそのまま重複加算しない。
6. 科目ごとの必修条件と、各区分・内数・上限・言語選択・提供コース条件を評価する。
7. 条件ごとに根拠、算入科目、算入単位、不足単位または未修得科目を返す。自然系の上限超過等、算入されなかった理由も示せるようにする。

`GraduationAssessment.new(curriculum:).call(completed:, registered:, planned:, unresolved:)`が実績・見込みの両Snapshotを返す。科目照合・算入・条件評価はこのModule内に集約し、画面へ分散させない。Repositoryは要件文書の取得を担い、判定そのものは担わない。文書構造と入力・出力は[データ契約](../config/curricula/README.md)を参照。

### 履修予定と初期状態（合意済み）

- 見込み判定の履修予定には、履修登録済み・履修中の科目に加え、本人が選んだ将来の科目も含める。
- 初期状態には、アプリのアカウント情報から得られる本人の過去の修得済み科目と、履修登録済み・履修中の科目を反映する。修得済み科目は実績判定と見込み判定の双方に使い、未修得の履修登録済み・履修中の科目は見込み判定にのみ使う。
- 本人がまだ選んでいない将来の科目は、デフォルトでは追加しない。便覧の履修モデルや必修科目から自動的に補完しない。
- 本人が将来の科目を追加した場合は見込み判定に用い、修得実績には加えない。

本人が追加した将来計画はアカウントに紐づけて保存し、次回利用時にも保存済みの計画を表示する。「将来計画がデフォルトで空」は、まだ計画を作っていない場合の初期状態を指し、再訪時に計画を消す意味ではない。履修データを再取込した場合の扱いは未確定。

将来計画は、卒業までに修得したい科目の一覧として保存する。予定年度・学期は保持せず、時間割・開講時期・履修時期の実現可能性を判定する機能は今回の対象に含めない。

### 当面の履修データ取得（合意済み）

- アカウントに紐づく保存済みダミー履修データの読み出しを実装した。`DemoData.load!`を明示的なseedで実行し、GETリクエストではレコードを作らない。
- 教務システムからの取得は将来の目標とし、軽量な取得方法が未確立のため今回の対象から外す。
- ダミー履修データと実際の学生の履修情報を区別し、教務システムとの連携や取得が実装済みであるとは扱わない。
- ダミー履修データを使うことは、未確認の卒業要件や科目分類を架空の値で埋めることを意味しない。

ダミーデータは`db/demo_enrollments.json`に分離し、修得済み・履修登録済み・履修中を明示する。`bin/rails db:seed`は繰り返し実行でき、保存済み計画や無関係な履修行を削除しない。実データへの切替方法は今回の範囲外。

### 利用アカウント（合意済み）

- 今回はローカル開発専用の固定デモアカウントを使う。
- 実際のアカウント登録・ログイン機能は今回の実装範囲に含めない。
- ダミー履修データの読み出しと将来計画の保存先は、このデモアカウントに紐づく学生とする。
- 将来計画はDBへ保存し、再訪時にも復元する。画面上だけの仮保存や、教務システム取得済みを装う動作にはしない。
- 認証なしのデモは外部公開しない。本番で固定アカウントを使って認証を迂回する構成にはしない。

### 判定できない入力（合意済み）

便覧外科目、分類不明、承認状況不明、科目の同一性不明などが結果を変え得る場合は、最終判定を「要確認」とし、「充足」や「不足」を断定しない。確認済み部分の結果は示す。この方針は実績判定・見込み判定の双方に適用する。

未知科目を黙って0単位にする方式や、卒業算入可能と仮定して加算する方式は避ける。対象外の特例は通常の不足とは区別して案内する。

## 8. 既存モデルとの接続と不足情報

- `Course.curriculum_key`で要件文書とDBを明示的に対応させる。値がある場合は一意だが、従来の番号・名称の重複は許容する。
- `StudentCourse`は`enrollment_status`をcompleted/registered/in_progress/failed/unknownとして保存する。既存行の既定値はunknownで、成績・NULL・年度から状態を推測しない。
- 修得済みは`credits_earned`を保持し、科目マスタの更新で書き換えない。承認は学生別の`approval_confirmed`で保持し、未確認の承認をtrueとして扱わない。
- `PlannedCourse`は学生・科目の組み合わせを一意に保存し、履修年度・学期を持たない。年度必須の実際の履修履歴へ架空の値を入れない。
- 判定は同じキーを一度だけ算入するが、元の複数履修記録は削除しない。配属履歴から未確認のプログラム別要件を作らない。
- `DemoController`は固定デモ学生の読出しと計画の追加・削除を提供する。GETは読出しのみ、POST/DELETEはDB保存後に303で再表示する。他学生の計画IDや利用者指定のstudent_idでは変更できない。
- 実アカウントの認証は今回の対象外。デモは開発・テストのローカルホストだけで利用し、ComposeのWebポートはloopbackへ限定する。Docker経由のプライベートIPは明示的な`LOCAL_DEMO_PROXY=1`のときだけ許可し、本番では常に拒否する。

## 9. 原本内の不整合と追加資料が必要な点

1. 提供科目表には知能327「ヒューマンコンピュータインタラクション」が重複掲載されている。2科目・4単位の根拠にはしない。
2. 専門科目分類表は知能情報特別講義Ⅰ〜Ⅵ、提供科目表と教育課程はⅠ〜Ⅳ。Ⅴ・Ⅵの番号・単位は推測しない。
3. ネットワークセキュリティ等に、自コース専門科目と自コース提供の工学融合枠の同名異番号がある。自コース融合枠の登録禁止を守り、名称一致で振り替えない。
4. 共通教育の科目別区分・言語・指定英語科目は追加一次資料で確認済み。専門基礎の系列混在・重複履修、同等科目の制度上の扱いは引き続き追加資料が必要なため、該当入力は要確認とする。
5. 便覧にない科目は注6で指導教員への相談が求められる。名称が似ているだけで自動的に読み替えない。
6. 他学部情報系科目の承認は学生別に確認し、未確認のまま算入しない。全教412の2単位は便覧13ページの履修モデルで確認済み。

## 10. 設計段階の算式の確認

実装前の一時的な算術確認として、人工的な集計値で12シナリオを実行し、期待した条件の成否と一致した。

- 最低構成130単位、英語二経路のうち英語8＋同一外国語4。
- 別外国語への分散、指定英語科目の欠落。
- 自然系の算入上限、自然系の過剰修得では埋まらない不足。
- 総合領域の合計条件と、他領域の超過では埋まらない不足。
- 工学融合の提供コース分散、内数22の不足、必修欠落、選択37の不足。

加えて、卒業研究Ⅰだけが未修得の実績（127単位）、同科目を予定に含めた見込み（130単位）、すでに修得した同科目を予定にも含めた場合（130単位のまま）の3スナップショットを実行し、期待値と一致した。これは同一性が既知の科目集合を用いた人工例であり、再履修の制度上の扱いを確定する検証ではない。

専門必修の科目数・小計・合計も計算で照合した。これは便覧解釈の算術確認であり、アプリの判定エンジン・実データ・全卒業要件の検証が済んだという意味ではない。
