# 講義を年度・学部・学科で分類し、一覧で絞り込めるようにする（設計）

- 対象issue: [#48](https://github.com/ore-orange/graduation-requirements-checker/issues/48)
- 前提ブランチ: `feature/course-registration`（[#26](https://github.com/ore-orange/graduation-requirements-checker/pull/26) の中身がそのまま入っている。`main` は未マージ）
- 日付: 2026-10-23

## 意図と、その理由

保存済みの講義の一覧は、**管理者だけが開く確認用の画面**である。開く場面は2つ。

1. 半年に一度、授業時間配当表のPDFを取り込んだあと、ちゃんと入ったかを確かめる
2. 誰かから「この講義の内容がおかしい」と連絡をもらったとき、その講義を探して確かめる

2つめが主な用途なので、一覧に最も必要なのは**引き当てる手段**、つまり科目名や講義コードでの検索である。分類（年度・学部・学科）は、その検索の範囲を絞るためにある。

いまの一覧は学期（前期・後期）で分けているだけで、知能情報コースのPDFにしか対応していない。共通教育や他学部のPDFを取り込むようになると、1つの表に年度も学部も混ざって並び、目的の講義を引き当てられなくなる。

学生向けの講義検索画面に育てる想定ではない。

## ゴール

- 講義（`course_offerings`）が、年度・開講学部・開講学科を持つ
- PDFの取り込みのときに、年度・学部・学科を人が選ぶ
- 保存済みの講義の一覧を、**年度 / 開講学部 / 開講学科 / 科目番号 / 講義コード / 科目名**の6つで絞り込める
- 年度が違えば別の行として積み上がる。来年取り込み直しても、去年の曜日・時限が残る
- 講義コードを必須にする。空の行は確認画面で確認済みにできず、保存にも進めない

## 非ゴール

- 学生が履修を組むための講義検索画面。この一覧は管理者のみ（`LocalAccessOnly` のまま）
- 教員名・授業の形態・全文検索での絞り込み。いまのデータに教員も授業形態も無い
- コース（`programs`、たとえば知能情報コース）単位の分類。学部・学科までで足りると決めた
- 共通教育・他学部のPDFを読み取れるようにすること（別issue）
- `courses` と `course_offerings` の統合（[#53](https://github.com/ore-orange/graduation-requirements-checker/issues/53)）

## アンチゴール

これが起きたら、動いていても失敗とみなす。

- 取り込み直すと、去年の年度の講義が上書きで消える
- 分類を足したせいで、取り込みの確認画面（PDFと見比べる画面）の操作が増える
- 絞り込みの条件を入れたあとページを送ると、条件が消えて全件に戻る
- 学部や学科の名前が入力のたびに揺れて（「工学部」「工 学部」）、同じ学部で絞り込めない

## 制約

- `course_offerings` は `main` に無く、このブランチにしか無い。既存データは開発者のローカルDBだけで、**消してよいと決めた**
- [#53](https://github.com/ore-orange/graduation-requirements-checker/issues/53) で `courses` に列を足して `course_offerings` を廃止する予定。今回足す2列はそのとき `courses` 側へ移るので、統合しても持ち方を変えなくて済む形（null 許容）にする
- 認証の仕組みが無いため、画面は開発・テスト環境のローカルアクセスのみ（既存の `LocalAccessOnly`）
- `course_offerings` のユニーク制約が `(semester, lecture_code)` なので、年度をまたぐと同じ講義コードを登録できない。これは変える必要がある

## 決めたこと

### 1. 学部・学科のマスタ

学部・学科は自由入力にせず、既存の `faculties` / `departments` を参照する。選択肢の元になるマスタを `db/seeds.rb` に入れる（`find_or_create_by!` で、何度流しても増えない）。

> **この表は要確認。** 琉球大学の公式サイト以外の情報源から書いたもので、学科名と構成は年度によって変わる。実装前に目を通してもらう。

| 学部 | 学科 |
|---|---|
| 人文社会学部 | 国際法政学科 / 人間社会学科 / 琉球アジア文化学科 |
| 国際地域創造学部 | 国際地域創造学科 |
| 教育学部 | 学校教育教員養成課程 |
| 理学部 | 数理科学科 / 物質地球科学科 / 海洋自然科学科 |
| 医学部 | 医学科 / 保健学科 |
| 工学部 | 工学科 |
| 農学部 | 亜熱帯地域農学科 / 亜熱帯農林環境科学科 / 地域農業工学科 / 亜熱帯生物資源科学科 |

DemoData が作る「デモ用工学部（架空データ）」はそのまま残す。これは架空の履修データ用で、取り込みの選択肢に混ざっても困らない（デモを有効にした環境でしか作られない）。

共通教育はこの表に無い。学部に属さない科目の置き場が要るが、読み取り対応が別issueなので、ここでは決めない（ビルダーに委ねる、下記）。

**名前の重複を防ぐ（私の判断）。** いま `faculties.name` と `departments.name` にユニーク制約が無く、`find_or_create_by!(name:)` で seed すると、名前を直したときに既存の行が改名されず**2つめの行ができる**。そうなると `course_offerings.department_id` は古い行を指したまま残り、「同じ学部で絞り込めない」というアンチゴールが起きる。そこで、

- `faculties.name` にユニークインデックスを張る
- `departments` に `(faculty_id, name)` のユニークインデックスを張る

学科コードのような別のキーは持たせない。15行ほどのマスタに対しては作りすぎになる。名前を直すときは、seed を直したうえで該当の行を `UPDATE` する（行数が少ないので手で足りる）。

**流す環境（私の判断）。** 学部・学科は架空のデモデータではなく実在のマスタなので、`db/seeds.rb` で**環境を問わず作る**（`DemoAccount.enabled?` の条件の外に置く）。`find_or_create_by!` なので何度流しても増えない。

### 2. DBの列

`course_offerings` に足す。

| 列 | 型 | |
|---|---|---|
| `year` | integer, **null 許容** | 開講年度（たとえば 2026） |
| `department_id` | bigint, **null 許容** | 開講学科への参照。学部は `departments.faculty_id` からたどる |

あわせて、既存の `lecture_code` を **`null: false`** に変える。講義コードは必ず振られるので、空であることはない。

**2列を null 許容にする理由。** [#53](https://github.com/ore-orange/graduation-requirements-checker/issues/53) でこのテーブルを `courses` と統合すると、`DemoData` が `curriculum_key` から作っている科目（学科も年度も持たず、`planned_courses` / `student_courses` から参照されている）が統合後のテーブルに同居する。それらは年度・学科を埋められないので、`null: false` にすると数週間後に制約を外すことになる。最初から null 許容にしておく。

ただし**取り込みからは必ず埋まる**。モーダルで年度・学部・学科を必須にするので、PDFから入った講義に空は無い。null になるのは、#53 のあとに残る `curriculum_key` 由来の行だけ。一覧の絞り込みは、それを「分類されていない講義」として扱えるようにする（「年度：すべて」のときに空の行も出る）。

**`year` は暦の年ではなく年度（私の判断）。** 2026年度の後期は、授業が 2026年10月〜2027年3月でも `year = 2026` になる。PDFに刷られている年度をそのまま入れる。こうしないと同じ年度の前期と後期が別の `year` に分かれ、年度での絞り込みも「年度の新しい順」の並びも、管理者の思う形にならない。既にある `student_courses.academic_year` と同じ意味・同じ型（integer、`1..9999`）にそろえるので、あとで突き合わせられる。

学部は `department_id` から一意に決まるので、学部の列は持たない。

ユニーク制約を `(semester, lecture_code)` から **`(year, semester, lecture_code)`** に変える。`lecture_code` が `null: false` になるので、いまの `where: "lecture_code IS NOT NULL"` という部分インデックスの条件は外し、ふつうのユニークインデックスにする。`CourseOffering` のモデル側も、`validates :lecture_code, presence: true` を足し、`uniqueness: { scope: :semester }` を `scope: %i[year semester]` に変える（`allow_nil` は外す）。

`year` に範囲の check 制約を付ける（`students.admission_year` と同じ `1..9999` にそろえる）。

`timetable_uploads`（確認中のPDF）にも年度・学科の2列を足す。こちらは取り込みのたびに作られて保存後に消えるテーブルなので、年度・学科は `null: false` にする（取り込みを始めるときに必ず選ぶ）。

**既存データはマイグレーションで消す。** `course_offerings` に入っているデータは消してよいと決めた（このブランチの開発中のデータしか無く、`main` にこのテーブルは無い）。`lecture_code` を `null: false` にする以上、空の講義コードを持つ行が残っていると通らないので、マイグレーションの中で

- `timetable_uploads` の行を消す（`timetable_upload_rows` は `dependent: :destroy` と外部キーで一緒に消える）
- `course_offerings` の行を消す
- 取り込みが作った `courses` の行を消す（**`curriculum_key` が nil のものだけ**）

の順に消してから、列を足す。

`courses` まで消すのは、`course_offerings` だけ消すと取り込みが作った科目が残り、取り込み直したときに `Importer` が「同じ名前・番号の講義が登録済みです」を全行に出して、PDF1枚ぶんすべてで「既存の講義として扱う」を選び直すことになるから。`DemoData` が作る科目は `planned_courses` / `student_courses` から参照されているので消せない。この2つは `curriculum_key` の有無で見分けられる（取り込みが作る科目は nil、`DemoData` の科目は値を持つ）。

`student_courses` / `planned_courses` から参照されている科目を誤って消さないよう、`curriculum_key` が nil でも参照のある科目は残す。消せなかった科目が残った場合は、その件数をマイグレーションのログに出す（取り込み直しで「既存の講義として扱う」を選ぶ必要があると分かるように）。

### 3. 取り込みのときに選ぶ

PDFアップロードのモーダル（`course_registrations/index.html.erb` の `dialog`）に、いまの「学期」のラジオボタンに加えて3つ足す。

- **年度** — プルダウン
- **開講学部** — プルダウン
- **開講学科** — プルダウン。選ばれた学部の学科だけが出る

3つとも必須。選ばずに送ると、いまのエラーのポップアップと同じ形で理由を出し、取り込みを始めない。

`TimetableUpload.build_from_pdf` が `year:` と `department_id:` も受け取って `timetable_uploads` に残す。確認画面でこれらを編集はできない（PDF1ファイル＝1つの分類なので、間違えたら取り込みを消してやり直す）。確認画面の見出しに「2026年度 工学部 工学科 前期」と出して、何を取り込んでいるかが分かるようにする。

`TimetableImport::Importer` は、いま `semester` を行から受け取っている。年度と学科は行ごとではなく取り込み全体で1つなので、**`Importer.new(rows, year:, department_id:)` の形で取り込み単位の値として渡す**（行のハッシュに毎行同じ値を詰めない）。

**講義コードは必須にする。** 講義コードは必ず振られるので、いまの `Importer#find_offering` にある「講義コードが無い行」の分岐（`course` + `semester` + `weekday` + `periods` で引き当てる側）を**なくす**。引き当てのキーは1つだけになる。

- `year` + `semester` + `lecture_code`

`department_id` はキーに入れない。講義コードは全学で一意なので、学科を間違えて取り込んだときは、重複行を作らずに同じ行の学科が直るほうが望ましい。

講義コードが空の行は、`Importer::RowAttributes` の検証でエラーにする（「講義コードが空です。」）。あわせて `TimetableUploadRow#problems` にも同じ検証を足し、**確認画面で講義コードが空の行は確認済みにできない**ようにする。そうしないと、手で足した行や読み取れなかった行が、保存のときになって初めて弾かれる。

科目（`courses`）側は変えない。同じ科目が年度をまたいで開講されても `courses` は1行のまま、`course_offerings` が年度ごとに増える。既存の科目と突き合わせる今の仕組み（「既存の講義として扱う」の選択）もそのまま。

### 4. 一覧の画面

講義登録の画面（`/course_registrations`）の「保存済みの講義」を、**検索バー + 1つの表**にする。分類ごとのカードや、分類ごとの別画面は作らない。

検索バーは GET のフォームで、条件はURLのクエリに載る。

| 項目 | 形 | 当たり方 |
|---|---|---|
| 年度 | プルダウン（「すべて」＋保存済みの年度） | 完全一致 |
| 開講学部 | プルダウン（「すべて」＋マスタの学部） | 完全一致 |
| 開講学科 | プルダウン（「すべて」＋選ばれた学部の学科） | 完全一致 |
| 科目番号 | テキスト | 部分一致、大文字小文字を区別しない |
| 講義コード | テキスト | 部分一致、大文字小文字を区別しない |
| 科目名 | テキスト | 部分一致 |

- 学期は絞り込みの軸にしない（**私の判断**。管理者が挙げた軸に入っていなかった）。表の列としては出す
- 年度・学科が空の講義（#53 のあとに残る `curriculum_key` 由来のもの）は、「すべて」のときに出す。表では空欄ではなく「—」と出して、値が無いことが分かるようにする
- 「条件を消す」で全件に戻せる
- 条件は**ページ送りのリンクに引き継ぐ**。`shared/_pagination` は `path` を lambda で受けるので、そこに条件を混ぜる
- 件数の表示（「42件中 1〜30件を表示」）は、絞り込んだあとの件数になる
- 1件も当たらなかったときは、「条件に当たる講義がありません」と出す。まだ1件も保存されていないときの今の文言（「まだ保存された講義はありません。…」）とは区別する

表の列は、左から **年度 / 学期 / 学部・学科 / 科目番号 / 講義コード / 科目名 / 単位 / 必修選択 / 年次 / 曜日 / 時限**。いまは学期ごとに `<h3>` で分けて表を2つ出しているが、それをやめて1つの表にし、学期は列にする。

並び順は、年度の新しい順 → 学期 → 曜日 → 時限 → id。

ページ送りは今の `Paginator` を使い、30件ずつのまま。

「確認中のPDF」の節は今のまま。各行の表示に年度・学部・学科を足す。

### 5. 直す文書

- `docs/database-design.md` — ER図と表に `year` / `department_id` を反映する
- `README.md` — 講義登録の説明に、取り込みのときに年度・学部・学科を選ぶことを書く。あわせて、**まっさらなDBでは `bin/rails db:seed` を流さないと学部・学科のプルダウンが空になる**ことを、開発の流れのところに書く

### 6. テストでのマスタの用意（私の判断）

`test/fixtures` には `files/` しか無く、fixture を使っていない。テストは必要なものをその場で作っている（`test/models/graduation_data_test.rb` が `Department` を作っているのがその例）。この形を変えない。

`course_offerings` の年度・学科は null 許容なので、既存のテストはそれだけでは壊れない。壊れるのは次の2つで、どちらも直す必要がある。

- `timetable_uploads` の年度・学科が `null: false` になるため、いま `TimetableUpload.create!(semester: '前期', …)` で作っているテスト（`test/controllers/course_registrations_test.rb`、`test/models/timetable_upload_test.rb`）
- `lecture_code` が必須になるため、講義コードの無い行を取り込んでいるテスト（`test/lib/timetable_import/importer_test.rb`）。「講義コードが無い行」の引き当てを確かめているテストは、その分岐ごと消す代わりに、**講義コードが空ならエラーになる**ことを確かめるテストに置き換える

そこで `test/test_helper.rb` に、学部・学科を1組だけ作って返す小さなヘルパーを足し、各テストはそれを呼ぶ。fixture は増やさない。

CI に seed の手順は足さない。テストはヘルパーで自前に用意するので、`db/seeds.rb` に依存しない。

## ビルダーに委ねること

- 絞り込みのクエリの置き場（`CourseOffering` のスコープか、専用のクラスか）
- 学部を選ぶと学科のプルダウンが切り替わる仕組み（Stimulus のコントローラか、学部ごとの `optgroup` を全部出して絞るか）。既存の `modal` / `dropzone` コントローラのやり方にそろえる
- 年度プルダウンに出す年度の範囲の決め方（取り込みの側。一覧の側は保存済みの年度から作る）
- 共通教育のような、学部に属さない科目の置き場。読み取り対応が別issueなので、必要になるまで `departments` に特別な行は作らない（列は null 許容だが、取り込みの画面では学科を必須のままにする）
- テストの置き方（既存の `test/controllers/course_registrations_test.rb` と `test/lib/timetable_import/importer_test.rb` に足す形で足りるか）
