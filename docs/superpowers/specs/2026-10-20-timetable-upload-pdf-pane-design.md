# 取り込みの確認画面で、PDFを並べて見ながら直せるようにする

2026-10-20 / 対象: 講義登録 → 授業時間配当表PDFの取り込み確認画面（`/timetable_uploads/:id`）

## なぜ作るか

確認画面には「必ずPDFと見比べて確認してください」と書いてあり、実際そうしないと使えない。
しかし今はPDFを別ウィンドウで開き、表の行に対応する行を自分で探している。38行ぶん、
1行ごとに「PDFのどこだったか」を探し直すのがいちばんの手間だった。
また、PDFにあるのに読み取れなかった科目は、画面から足す手段がなく、取り込み後に手作業が残る。

## ゴール / 非ゴール / アンチゴール

**ゴール**

- PDFが同じ画面にあり、見比べるのに窓を行き来しなくてよいこと。
- PDFの見え方（位置・大きさ）を自分で決められること。
- 読み取れなかった科目を、その場で、PDFと同じ並びに足せること。
- 確認中の操作が軽いこと（1行ごとに画像生成やPDF描画が走らない）。

**非ゴール**

- PDFビューア全般（検索、注釈、印刷、原本のダウンロード）。
- 取り込みが終わったあともPDFを保管すること。
- 行がPDFのどこかを自動で指すこと（最初にこの形を試したが、本人が「自分でスクロールしたい」と判断した）。

**アンチゴール**

- 行を直している最中に、入力した値が消えること。
- PDFの読み込みや画像化のせいで、取り込み自体が失敗すること。

## 決めた形（画面）

ブラウザのモックで本人が触って決めた形。モック: `.superpowers/brainstorm/25801-1792482349/content/mock-scroll-and-add.html`
（使い捨て。アプリのCSSを借りているので、ローカルのRailsが動いている状態で見る）

**PDFペイン**

- 表の見出しの上に、PDFのページを縦に並べたペインを置く。ペインも見出しも貼り付く（`sticky`）ので、
  表をスクロールしてもPDFは画面に残る。中は自分でスクロールする。
- 上のバーに、ページ送り（1 / 2 / 3…）、倍率（スライダー・数値入力・＋−）、「幅に合わせる」、「PDFを隠す」。
- 既定は**幅に合わせる**。開いた時点でページ全体の幅が収まっている状態から始める。
- ページは**中央揃え**。ペインより狭いときは真ん中に置き、広いときは中央が見えた状態で開く。
- 倍率を変えても、まん中に見えていたところがまん中に残る。
- ペインの高さは、枠の右下をつかんで変えられる（`resize: vertical`）。
- 画像が無い取り込み（この変更より前のもの、画像化に失敗したもの）では、ペインごと出さない。

**読み取れなかった科目の追加**

- 追加ボタンは、いつも画面にある下の固定バーに置く。スクロールせずに押せること。
- 押すと、**最後に触った行のすぐ下**に空の行が入る。ボタンの横に「610011071 の下に」と行き先を出す。
  どの行にも触れていなければ、表のいちばん下に入る。
- 続けて押すと、足した行のさらに下に増える（PDFで続けて抜けていた科目をそのまま並べられる）。
- 足した行は色を変え、「手で追加した行」と出し、消せるようにする。
- 足した行は読み取った行と同じ欄・同じ検証で、確認済みにすれば一緒に保存される。

## 決めた形（作り）

### 1. ページ画像を取り込み時に1回だけ作る

- アップロード時、解析と同じ `gs` でページをPNGにする（`-sDEVICE=png16m -r150`）。
- 実測（38行・3ページのPDF）: 0.33秒 / 合計0.2MB / 1ページ 2113×1494px。
- 置き場所は `storage/timetable_uploads/<upload_id>/p<ページ番号>.png`。`storage/` はgitignore済みで、
  コンテナでもホストのディレクトリに残る。
- 元のPDFは保管しない。見せるのは画像だけで足りる。
- 画像化に失敗しても取り込みは成立させる（ペインが出ないだけ）。取り込みの成否を、見比べ用の画像に引きずらせない。

### 2. 画像の配信と後始末

- `TimetableUploadsController` に画像を返すアクションを足す（`send_file`）。
  同コントローラの `LocalAccessOnly` がそのまま効くので、ローカル以外には出ない。
- 取り込みを破棄したとき・保存して消えたときに、ディレクトリごと消す。モデルの削除に乗せる。

### 3. 行の追加・削除は、今のフォームの送信に乗せる

- 追加・削除のボタンは、行の編集と同じフォームの送信ボタンにする（`operation=add_row` / `destroy_row_id=<行ID>`）。
  別のリンクやボタンで飛ばすと、入力中の値が保存されずに消える（アンチゴール）。
- 追加した行は、指定した行の次の位置に入れ、後ろの行の位置をずらす。
- 手で足した行だとわかるように、行に印を持たせる（`added_by_hand`）。見た目と削除ボタンはこの印で出し分ける。

## すでに入れた変更（この設計の前提）

同じ画面に対して、ここまでに入れて動いているもの。

- 時限を、候補から選べて自由にも打てる欄にした（`combobox` コントローラ。3コマ以上の並びに対応）。
- 講義コードを左端に移し、備考の列をなくした（PDFで見るため）。PDFと列の並びが揃う。
- ページ送りをなくし、全行を1画面に出すようにした。
- 「確認済み」のチェックは、押した時点で保存する。更新ボタンと「◯行を更新しました」の知らせは廃止。

## 残る制約

- 画面幅: PDFの表は横に長い。既定の「幅に合わせる」だと文字は小さめになるので、読みたいときは倍率を上げる前提。
- `gs` は取り込み（テキスト抽出）に元から必要なので、新しい依存は増えない。
- 実物の配当表PDFは本人の手元（`~/Desktop/講義一覧pdf/`）にある。個人の資料なのでリポジトリには入れない。
  テストは今まで通り、合成XMLと画像化のスタブで書く。
