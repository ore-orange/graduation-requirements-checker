# 便覧の下書き編集画面を、確認できる量まで削る 設計

2026-11-13 / 対象ブランチ: `feature/curriculum-import`
前提: [2026-11-10 要件表の確認画面の作り直し](2026-11-10-requirements-review-redesign-design.md) の続き。あの作り直しで入れたツリー・枠・チップはそのまま使う。

## なぜ直すのか

前回の作り直しで「1行が画面の1行に収まる」ところまでは来た。それでも画面が確認に使える状態になっていない。

ユーザーの言葉:

> * 編集画面の読むページという概念がよくわかりません
> * 小さい文字が多すぎます。出典は1箇所だけ表示させとけば大丈夫です
> * 経路やグループの分け方、グループの呼び方等は直感的ではなく、わかりづらいので、区分選択時に対象科目を取得する仕組みにできないか、または他にもっと良い実装方法はないか
> * 科目表には共通教育科目や他学部の科目は必要なく、自コースの情報技術系・総合力演習等の区分のみ見ることができればOK

さらに、決まりを見せる理由そのものへの問い:

> そもそも決まりを見せる理由がわからないです。利用者側からすると、区分には対象科目が設定されており、それは下の科目表から確認できる様になっていますよね？外国語の決まりもORで利用者側とシステム両方が分かりますし、なぜ見せる必要があるのか分かりません。

### 実測

2024年度の下書き(`/curricula/13`)を 1440×1000 で開いて測った。

| | 高さ | 画面(1000px)何枚分 |
|---|---|---|
| 画面全体 | 39,390px | 約40枚 |
| 要件表の確認 | 10,547px | 約11枚 |
| 科目表の確認 | 27,937px | 約28枚 |

- 決まりの箱: **27個**
- 「出典 …」の行: **27本**(中身は2種類しかない)
- `.text-xs` が付いた要素: **633個**
- 科目表の行: **506行**(科目484 + 節の見出し22)

### 決まりの箱27個を、1つずつ突き合わせた

「決まりを見せる理由」は、仕組みの説明ではなく、**AIがPDFから読んだ数字を人がPDFと突き合わせるため**。だから、上の行・章・枠がもう同じ数字を出しているなら、見せる理由がない。

**12個が、持ち主(行・章・枠)と文字通り同じ**(同じ必要単位・同じ区分)。いま画面にはこう出ている:

```
● 数学基礎（必修）              [6] 〜 [ ] 単位      ▸科目 3件  …
  対象： 数学基礎（必修） ×   ＋ 区分を足す
  ┌ 数学基礎必修  区分の合計単位                    [6] 〜 [ ] 単位  …
  │ 出典 docs/kogaku_chinot_y24.pdf（便覧10ページ・PDF11ページ）
  │ 数える区分
  │ 数学基礎（必修） ×   ＋ 区分を足す
  └
```

同じことを二度書いている。該当するのは `total`(総単位の枠) `common_total`(章1) `health` `general_subtotal`(行「教養・総合領域」) `basic_total`(章2) `required_information` `required_comprehensive` `required_research` `required_math` `required_core` `elective_total`(章4) `elective_inner`(枠) の12個。

**残り15個は、行の形では書けないことを言っている。** ここは区分と科目表からは読み取れない:

| 持ち主 | 行が言えていること | 行が言えていないこと |
|---|---|---|
| 行「教養・総合領域」 | 14単位／6区分 | 人文2以上・社会2以上・総合系2以上・**自然系を除いて12以上**・自然系は2単位まで |
| 行「基幹領域：外国語科目」 | 12単位／英語+外国語 | 英語12、**または** 英語8＋同一言語4。加えて外101・外102は必須 |
| 行「基幹領域：日本語表現法入門」 | 2単位／日本語表現法入門 | 情11 日本語表現法入門を修得していること |
| 行「専門基礎科目」 | 6単位／専門基礎 | 微積ＳＴⅠ＋Ⅱ、**または** 微積入門Ⅰ＋Ⅱ。物理学Ⅰ、または物理学入門Ⅰ |
| 行「工学融合科目」 | 4単位／工学融合 | **同じ提供コースから**4単位(他コースを合算しない) |
| 章「3. 専門必修科目」 | 57単位 | 科目表の必修31科目を**すべて**(1つ落ちたら不足) |
| (持ち主なし) | — | 専門必修の合計57単位 / 自然系は便覧全体で2単位まで / 算入しない科目2件 |

つまり **27個 → 15個**。残る15個も、下記3のとおり日本語の1行に書き直す。

外国語のORについては、ユーザーの言うとおりORがあること自体は自明。ただし「**8**＋**4**」なのか「**6**＋**6**」なのかはAIがPDFから読んだ数字で、画面の他のどこにも出ていない。ここは残す。

### 経路の欄が、いま実際にどう見えているか

行「基幹領域：日本語表現法入門」の決まりを開くと、こう出る:

```
経路1(すべて修得して1つの経路)
 ☐ calculus_intro_1(微分積分学入門Ⅰ)   ☐ calculus_intro_2(微分積分学入門Ⅱ)
 ☐ calculus_st_1(微分積分学ＳＴ（スタンダードコース）Ⅰ)   ☐ calculus_st_2(…Ⅱ)
 ☐ english_reading_intermediate(英語講読演習 中級)   ☑ japanese_expression(日本語表現法入門)
 ☐ physics_1(物理学Ⅰ)   ☐ physics_intro_1(物理学入門Ⅰ)   ☐ university_english(大学英語)
```

「日本語表現法入門を修得していること」を表すのに、**便覧じゅうの役割キー9個**を英語のまま並べ、関係のない微分積分学や物理学も混ぜて出している。`grouped_max` は「グループの分け方」に `field:language` / `number_prefix` を手で打たせ、「グループの呼び名」を別の欄で打たせている。これが「直感的ではなく、わかりづらい」の中身。

## 目標

- 決まりの箱を、**行・章・枠が言えていないものだけ**にする。
- 画面からアプリ内部の語彙(役割キー・`field:language`・`number_prefix`・区分キー)を消す。人が打つのは科目名と区分名と数字だけ。
- 出典を1箇所にし、本文の文字を読める大きさに戻す。
- 科目表の確認で、自コースの専門区分だけを見れば済むようにする。
- 「読むページ」が何の作業なのかを、画面を見れば分かるようにする。

## 目標でないもの

- 判定エンジン(`GraduationAssessment`)の**判定結果を変えない**。同じ便覧なら、前後で学生に出る数字は同じ。
- 公開済みの便覧の形(`PublishedDocument` が通す欄)を減らさない。2024・2025年度の便覧がそのまま読めること。
- 学生に出る画面(`/requirements`・ダッシュボード・履修計画)の作り直し。ただし下記「拾った小さな傷」の1件だけは直す。
- 科目表のデータから共通教育の科目を落とすこと(下記の理由により、落とさない)。

## 失敗とみなすもの(アンチゴール)

- **減らすのは「人が打つ欄」であって「人が見る値」ではない。** 決まりの箱を隠した結果、判定を決める値が画面のどこにも出なくなったら失敗。隠してよいのは、同じ値が持ち主の行・章・枠にそのまま出ている箱だけ。
- 「触らずに保存しても、文書が1バイトも変わらず、人が確認した印も付かない」が壊れること。既存テストが守っている。
- 同じ値を2か所から送ってしまうこと(同名パラメータの重複)。`claim_rule_box?` の仕組みを壊さない。
- `test/fixtures/files/graduation_golden_2024.json` が変わること。変わったら設計か実装が間違っている。

## 検討した作り

**(ア) 決まりの箱に手を入れず、文字を大きくし出典を畳む。** 一番安いが、ユーザーの問い(「そもそも決まりを見せる理由がわからない」)に答えていない。27個の箱のうち11個が重複という事実が残る。採らない。

**(イ) 決まりの箱を全部やめ、行・章・枠の欄だけにする。** いちばん短くなるが、「人文2以上」「英語8＋同一言語4」「同じ提供コースから」が画面から消える。アンチゴールに正面からぶつかる。採らない。

**(ウ) 持ち主が言えていることは出さない。言えていないものだけ出す。**(採る)
重複している箱を隠し、その欄を持ち主の行・章・枠に移す。残る箱は、人が読める日本語に書き直す。見る値は1つも減らず、打つ欄が減る。

ユーザーはこの形で合意済み(「畳まずに見えている形でお願いします」)。

## 決まったこと

### 1. 決まりの箱を隠す条件

**「持ち主」は、文書で指している数ではなく、画面がその箱を描く場所。** 文書では `basic_total` を章と行の両方が、`elective_inner` を枠と3つの行が指している。画面は同じ決まりを2か所に出さない仕組み(`RequirementsReview#claim_rule_box?`)を既に持っていて、先に描いたほうが取る(総単位の枠 → 章 → 枠 → 行)。**その、先に取った1か所を持ち主とする。**

箱を隠すのは、次を**すべて**満たすときだけ:

- 決まりの型が `credit_sum`
- 持ち主の `required_credits` が、決まりの `required_credits` と等しい
- 持ち主が数える区分と、決まりの `categories` が集合として等しい
  - 行 … 行の `categories`
  - 章・枠 … その中の行の `categories` の合併
  - 総単位の枠 … `counts_toward_total` が false でない区分すべて
- その決まりに、突き合わせの指摘(`findings`)も入力の問題(`problems`)も付いていない

ひとつでも外れたら、今までどおり箱を出す。**安全側(出す側)に倒す。**

最後の条件は、箱を隠すと指摘の出る場所も消えてしまうため。上のまとめ(`_requirements_findings`)には「規則: `elective_inner`」のように id だけが残り、その id を画面のどこからも辿れなくなる。指摘の付いた決まりは必ず箱を出す。

2024年度の実データで、この条件に当たるのは上に挙げた12個。章・枠の「中の行の区分の合併」は4件すべて一致することを確認済み。

### 1-2. 持ち主が別にいる行は、単位の欄を読むだけにする

章・枠が先に取った決まりを、その中の行も指していることがある。このとき行の `required_credits` は、**判定が使っていない数字**になる。実データの3行:

| 行 | 行に出ている数字 | その数字の決まりを持っているのは |
|---|---|---|
| 専門基礎科目 (微分積分学・物理学) | 6単位 | 章「2. 専門基礎教育」 |
| 知能情報アドバンスト | 22単位 | 枠「数学基礎（選択）・アドバンスト・関連の合計」 |
| 専門科目（自由） | (空) | 章「4. 専門選択科目」 |

ここを入力欄のまま残すと、§2 が消そうとしている落とし穴がこの3行に残る(直しても判定が動かない)。そこで、**自分の数字の決まりを持っていない行は、単位の欄を入力欄にせず、どこに単位があるかを文で出す。**

```
  ● 知能情報アドバンスト        上の枠「…の合計」の22単位に含む        ▸科目 18件  …
    対象： 知能情報アドバンスト ×   ＋
```

`display.rows[].required_credits` の値は書き換えない(学生の画面に出ている数字なので、画面が勝手に消さない)。欄を入力にしないだけ。欄が無ければブラウザも送らないので、「触らずに保存して1バイトも変わらない」も守れる。

### 2. 隠した決まりは、持ち主の欄が書く

これは前回の設計書 項目5 の「行の `以上〜以下` は `display.rows[].required_credits` だけを読み書きし、入れ子の決まりの数字には書き込まない」を**変える**。

変える理由は2つ。

**(a) いまは落とし穴になっている。** `display.rows[].required_credits` は学生の画面に出す数字で、判定は `rules[].required_credits` を見る。だから「情報技術系 2単位」を3に直して保存しても、学生の判定は2単位のまま。両方を直さないといけないのに、画面はそれを教えてくれない。

**(b) 前の規定の理由が、この条件では当たらない。** 「どの入れ子に書くべきか決められない行がある」から書かない、という規定だった。隠す条件を「ただ1つの `credit_sum` を指し、単位も区分も一致している」に絞ったので、書き先は一意に決まる。決められない行(教養・外国語)は、条件を外れるので箱が出たまま。そこは今までどおり別々に直す。

書き方:
- 行・章・枠・総単位の `required_credits` を変えたら、隠れている決まりの `required_credits` にも同じ値を書く。
- 行の `categories` を変えたら、隠れている決まりの `categories` にも同じ集合を書く。
- **行の区分を変えたら、その行を含む章・枠が隠している決まりの `categories` も、新しい合併に合わせて書く。** 波及させないと、隠れた決まりが古い区分を数え続け、それが画面のどこにも出ない(落とし穴が形を変えて残る)。
- 値を変えていないときは**何も書かない**(「触らずに保存しても1バイトも変わらない」を守る)。波及も、行の区分が実際に変わったときだけ走る。
- 「人が確認した」印は、持ち主と決まりの両方に付く。

走る場所は `RequirementsEdit#apply_sections` の `edit_rules` と `edit_display` の**あと**。両方が終わってから、持ち主と決まりを突き合わせて書く(先に走ると、同じ保存の中で人が決まりを直していたときに上書きしてしまう)。人がその決まりの箱を直接直していたら(箱が出ていたということなので)、そちらを優先して波及させない。

### 2-2. 隠した決まりが持っている「学生に出る文言」

`label` と `detail` は、学生のカードに出る値(`Rules::Base#label` / `#detail`)。実データでは隠す候補の3つが `detail` を持っている:

- `total` …「共通教育＋専門基礎＋…自然系は全体でも上限2単位。」
- `elective_inner` …「専門選択37単位の内数。工学融合・自由科目はこの22単位に含めません。」
- `general_subtotal` …「健康運動系は含めず、自然系は最大2単位。」

箱を隠すとこれを直す手段が画面から消え、アンチゴール(「減るのは人が打つ欄であって、人が見る値ではない」)に触れる。**持ち主の `…` の中に「学生の画面に出す説明」として移す。** 行・章・枠・総単位の `…` に欄を1つ足すだけ。`label` も同じところに置く(行の名前とは別の値)。

### 3. 残る決まりを、日本語で書き直す

#### 3-1. 経路(`one_of_paths`)— 役割キーをやめ、科目を選ぶ

```
● 基幹領域：日本語表現法入門                     [2] 〜 [  ] 単位   科目 1件 ▸
  対象： 日本語表現法入門 ×   ＋ 区分を足す
  ┌ この行には、さらに次の決まりがあります ────────────────┐
  │ 次の科目をすべて修得                                      │
  │   情11 日本語表現法入門 ×       ＋ 科目を足す               │
  └─────────────────────────────────┘
```

複数の経路があるときは、組を縦に並べる:

```
  ┌ この行には、さらに次の決まりがあります ────────────────┐
  │ 次のどれか1組を、すべて修得                                │
  │   ・ 先11 微分積分学ＳＴⅠ ×   先12 微分積分学ＳＴⅡ ×   ＋   │
  │   ・ 転03 微分積分学入門Ⅰ ×   転04 微分積分学入門Ⅱ ×   ＋   │
  │   ＋ 組を足す                                            │
  └─────────────────────────────────┘
```

「経路」という言葉は画面から消す。「次のどれか1組を、すべて修得」と書く。

**科目の選び方。** 「＋ 科目を足す」は2段。まず区分を選び、その区分の科目から選ぶ。既定の区分は、その行が対象にしている区分(無ければ全部)。1つの選択肢に484科目を並べない。

**役割キーはアプリが裏で振る。** 文書の `paths` は今までどおり役割キーの配列を持つ。画面が科目を選んだら:
- その科目がすでに役割を持っていれば、その役割を使う。
- 持っていなければ、その科目の `key` をそのまま役割キーにし、`courses[].roles` にも足す。

**役割は `courses[].roles` に置くしかない。** 文書には top-level の `roles`(キーと名前の一覧)もあるが、判定の `Catalogue#role_candidates` は `course['roles']` しか見ない。top-level の `roles` は突き合わせ(`Validation::RuleChecks#roles`)が使う宣言の一覧で、判定には効かない。

**そのままだと、科目表を読み直したときに消える。** `DraftMerge#course_entry` は読み直しで科目を作り直し、`'roles' => Array(row['roles'])`(AIの答え。通常は空)で入れ替える。守られるのは「人が確認した」科目と手で足した科目だけ。要件表の画面が足した役割は黙って消え、`one_of_paths` は「役割を持つ科目が科目表にありません」で必ず要確認になる。

そこで、**`DraftMerge` の科目の読み直しで、すでにある役割を消さない**(新旧の役割を合わせる)。役割は要件表の画面が決める値で、科目表のページから読む値ではないので、読み直しで入れ替える理由がない。役割は `one_of_paths` の関門にしか効かないので、この変更で単位が増える方向には動かない。

役割を足した科目に「人が確認した」印は**付けない**。印は「この科目の単位・区分をPDFと見比べた」という意味で、科目表の画面のワークフローに属する。要件表の画面が勝手に付けると、AIの読み直しがその科目の単位を直せなくなる。

チップを `×` で外したとき、その役割をどの決まりの経路も名指ししていなければ、`courses[].roles` からも取り除く。ほかの決まりがまだ名指ししていれば残す。

これで `Catalogue#role_candidates` はそのまま動く。既存データは役割1つ=科目1つなので、**判定結果は変わらない**。

**科目が複数ある役割(将来)。** 1つの役割に複数の科目がぶら下がる形は、文書としては書ける(「どれか1つを修得すればよい科目の束」)。画面はその役割を「情11 日本語表現法入門 ほか2件」のように1つのチップで出し、押すと中身を見せる。画面からその束を作ることはできない(作る手段が要るという話が出たら、別の作業にする)。

#### 3-2. 区分の合計(`credit_sum`)が残ったとき

持ち主と食い違っていて残った箱は、短い1行にする。型の名前(「区分の合計単位」)も `id` も出さない。

```
● 教養・総合領域 (人文・社会・自然・総合等)        [14] 〜 [  ] 単位   科目 249件 ▸
  対象： 人文系 × 社会系 × 自然系 × 総合科目 × キャリア関係 × 琉大特色・地域創生 ×   ＋
  ┌ この行には、さらに次の決まりがあります ────────────────┐
  │ 人文系 から                           [2] 単位以上          │
  │ 社会系 から                           [2] 単位以上          │
  │ 総合科目・キャリア関係・琉大特色・地域創生 から [2] 単位以上      │
  │ 自然系を除いて                         [12] 単位以上         │
  │ 自然系 は                             [2] 単位まで（便覧全体で） │
  │ ＋ 決まりを足す                                           │
  └─────────────────────────────────┘
```

区分のチップと単位の欄は今までの部品をそのまま使う。変えるのは並べ方と言葉。

`general_without_natural`(自然系を除く5区分で12単位)を「自然系を除いて」と書けるのは、その決まりの区分が「行の区分 − 1個」のとき。一般には区分名を並べる。

#### 3-3. 同じ提供元・言語から(`grouped_max`)

「グループの分け方」のテキスト欄と「グループの呼び名」の欄をやめ、1つの選択肢にする。

```
  │ 工学融合科目 のうち、同じ 提供コース ▾ から   [4] 単位以上      │
```

選択肢は2つ:

| 画面の言葉 | 書き込む値 | `group_label` |
|---|---|---|
| 提供コース(科目番号の先頭) | `number_prefix` | `提供コース` |
| 言語 | `field:language` | `言語` |

**いまの値が2択に無ければ、現在値を3つめの選択肢として残す。** `Validation::RuleShape#grouped_max` が通すのは `number_prefix` / `number_prefix_hundreds` / `field:<任意の欄>` の3形。2択に絞ると、別の便覧でAIが `number_prefix_hundreds` や `field:credits` と読んだ決まりが、**画面を開いて保存しただけで `number_prefix` に書き換わり**、判定が変わったうえ元の値がどこにも残らない。この画面は未知の便覧を読むための画面なので、知らない値は「いまの設定: `field:credits`」として選択肢に並べ、選び直さないかぎり触らない。除外の提供コース(`number_prefixes`)が既に同じ作りになっている。

`group_label` の欄は画面から消すが、**書くのは人が `group_by` を選び直したときだけ**。AIが「開講コース」など別の呼び名で読んだ既存の値を、画面を開いただけで上書きしない。

`number_prefix` の決まりには `group_label` が無く、学生の画面に「同一の**科目番号の接頭辞**から」と出ている(`RuleSentenceHelper::GROUP_BY_NAMES`)。これも「提供コース」に直す(下記「拾った小さな傷」)。

#### 3-4. どれか1つ／すべてを満たす(`any_of` / `all_of`)

「種類」のプルダウンに内部の型名を並べるのをやめ、残る形だけを出す。

```
● 基幹領域：外国語科目                           [12] 〜 [  ] 単位   科目 71件 ▸
  対象： 英語 × 英語以外の外国語 ×   ＋
  ┌ この行には、さらに次の決まりがあります ────────────────┐
  │ 次の科目をすべて修得                                      │
  │   外101 大学英語 ×   外102 英語講読演習 中級 ×   ＋ 科目を足す  │
  │                                                      │
  │ かつ、次のどちらかを満たす                                 │
  │   ・ 英語 から [12] 単位以上                               │
  │   ・ 英語 から [8] 単位以上                                │
  │     かつ 英語以外の外国語 のうち、同じ 言語 ▾ から [4] 単位以上  │
  │   ＋ 満たし方を足す                                       │
  └─────────────────────────────────┘
```

入れ子の段数・置ける型(`ANY_OF_OPTIONS` / `ALL_OF_CONDITIONS`)は今までどおり。変えるのは見せ方と言葉。

#### 3-5. 必修をすべて修得(`all_required`)

章に出す。`expected_course_count` は「科目表の転記漏れを見張る数」なので残すが、言葉を変える。

```
章 3. 専門必修科目                                [57] 〜 [  ] 単位
  ┌ この章には、さらに次の決まりがあります ────────────────┐
  │ 科目表で必修になっている科目を、すべて修得                    │
  │ 便覧に書いてある必修の科目数 [31] 科目（科目表の必修は 31 科目）  │
  └─────────────────────────────────┘
```

科目表の実数を横に出す。食い違っていれば、そこで分かる。

#### 3-6. どこからも指されていない決まりは、箱を出したまま

`required_total`(専門必修の合計57単位)は、値としては章「3. 専門必修科目」の57と重複しているが、**どこからも指されていない**(章の `check_id` は `required_all` で埋まっていて、`display.groups[].check_id` は単数。配列にするのは「文書の形を変えない」制約に反する)。

持ち主がいないので、§1 の条件に当たらない。今までどおり「どの行にも結びついていない決まり」の枠に箱を出す。隠して誰も書かないと、判定が使う57が画面のどこにも出ず、直す手段も無くなる。

### 4. 出典は節に1箇所

決まりごとの「出典 …」をやめる。「要件表の確認」の見出しの下に1行だけ出す。

```
要件表の確認
出典: 便覧10ページ・PDF11ページ ／ 便覧1・10・11ページ・PDF2・11・12ページ
```

文書の `rules[].source_page` は今までどおり持つ(消さない)。画面が、出てくる値をユニークにして並べるだけ。2024年度は2種類、2025年度は1種類。

ばらばらの値が4つ以上になったら、そのときだけ決まりの横に小さく出す(人が「この数字はPDFのどこか」を追えなくなるため)。

### 5. 文字の大きさ

- 本文・入力欄・チップ・ボタンの既定を `text-xs` から **`text-sm`** に上げる。
- `text-xs` に残すのは、見出しの脇の補足(「人が確認した」「内数」「◯件」)だけ。
- 節の長い説明文は、2文までに削る。

`.rv-field` `.rv-chip` `.rv-slot` `.rv-more` `.cr-chip` のCSSで大きさを決めているので、ここを直せば行ごとの直書きは要らない。

### 6. 科目表の確認は、節を畳んで出す

科目表の確認が 27,937px あるのは、484科目を全部広げているため。

**節(区分)を既定で畳む。** 見出しだけを並べ、押すとその区分の科目が開く。

```
科目表の確認
  最初に見る科目 ・ 3科目                                  (開いたまま)
  ▸ 健康運動系 ・ 2科目 ・ 必修0単位 ・ 未確認2件
  ▸ 人文系 ・ 54科目 ・ 必修0単位 ・ 未確認54件
  …
  ▸ 情報技術系（必修） ・ 2科目 ・ 必修2単位 ・ 未確認2件
  ▸ 総合力演習（必修） ・ 4科目 ・ 必修7単位 ・ 未確認4件
```

これで22個の見出し(約1,500px)になり、見たい区分だけを開く。

**「まとめて確認する(N科目)」は、畳んだ見出しから外して開いた中に移す。** いまこのボタンは節の見出しにあり、コードのコメントは「PDFと見比べずに押せてしまう操作なので、何件に効くかを隠さない」としている。科目を畳んだまま押せる場所に残すと、一度も見ていない54科目に一撃で「人が確認した」印(＝読み直しから守る印)を付けられる。開いた中なら、少なくとも科目が画面に出ている。

**「自コースの区分」をアプリが推測しない。** 共通教育の区分には科目番号のパターン(`健`・`人`・`外1`…)があり専門には無い、という当てはめもできるが、`japanese`(日本語表現法入門)が共通教育なのにパターンを持たないので外れる。推測して外すより、全部畳んで人が開くほうが確か。

**「最初に見る科目」は今までどおり開いたまま先頭に出す。** ここが見落としの入口なので畳まない。

**共通教育の科目をデータから落とさない。** 484科目のうち352科目が共通教育(別PDF「共通教育等授業科目表 別表1」由来)で、落とせば科目表は軽くなる。しかし:
- `english_required` が名指しする外101 大学英語・外102 英語講読演習 中級は共通教育の科目。
- `foreign_language` の `grouped_max` は、科目の `language` 欄を見て言語別に数える。科目番号のパターンではこの欄が作れない。

落とすと、この2つの決まりが判定できなくなる。「判定結果を変えない」に反するので、データは残す。

### 7. 「読むページ」を、手順の①にする

「読むページ」は、便覧PDFの各ページに「科目表／要件表／読まない」を付けて、AIに1ページずつ読ませる**取り込みの操作**。確認・編集と同じ画面に、順番の印もなく並んでいるのが分かりづらさの元。

**(a) 画面を番号付きの手順にする。** 節の見出しを `① PDFを読み取る` `② 要件表を確認する` `③ 科目表を確認する` `④ 公開する` にし、上の「確認する場所」のリンクも同じ言葉にする。

**(b) ページのサムネイルを出す。** これが一番効く。いまは「1ページ」「2ページ」という番号だけで、**どのページが要件表なのかを画面から知る手段がない**。別のPDFビューアで便覧を開いて数えるしかない。`page_image` のルートとアクションは既にあり、科目表のPDFペインが使っている。同じ画像を各行に小さく出す(`loading: "lazy"`)。

```
① PDFを読み取る
便覧PDFのページを1枚ずつAIに読ませます。どのページが要件表で、どのページが科目表かは
便覧ごとに違うので、サムネイルを見て指定してください。

  ┌──────┐
  │(10頁の │  10ページ    ◉ 読まない  ◯ 科目表  ◯ 要件表
  │ 画像)  │
  └──────┘
  ┌──────┐
  │(11頁の │  11ページ    ◯ 読まない  ◯ 科目表  ◉ 要件表   読み取り済み  [読み直す]
  │ 画像)  │
  └──────┘
```

**(c) 説明文を短くする。** いまの3文を2文に。

種別を選ぶ → 「ページの指定を保存」 → 「読む」の3操作はそのまま残す(保存を挟まずに読ませると、読んだ種別と保存した種別が食い違う)。

### 8. 拾った小さな傷

実際に画面を開いて見つけたもの。どれも小さいが、全部直す。

| 場所 | いま | 直す |
|---|---|---|
| 行と決まり | 同じものを「対象：」と「数える区分」と2つの言葉で呼んでいる | 「対象：」に統一 |
| 区分の一覧 | 区分名の横に内部キーを出している(`健康運動系 (health)`) | 消す。人は一度も打たない値 |
| 算入しない科目 | 「算入しない理由」のラベルが、上の欄の行に重なって出る | グリッドを組み直す |
| 算入の上限 | 名前と型名が同じ(「算入の上限 算入の上限」)で二重に出る | 型名を出さない |
| 章の決まり | 章の下に、中の行と同じ区分チップが10個並ぶ | 上記1で隠れる |
| 学生の画面 | `grouped_max` が「同一の**科目番号の接頭辞**から4単位以上」と出る | 「同一の**提供コース**から」(`GROUP_BY_NAMES`) |

## 制約

- **判定結果を変えない。** `test/fixtures/files/graduation_golden_2024.json` は変えない。
- **既存の不変条件を守る。** 触らずに保存したとき、文書が1バイトも変わらず「人が確認した」印も付かないこと。
- **同名パラメータを2か所から送らない。** `review.claim_rule_box?` の仕組みを使い続ける。隠した箱は欄を持たないので、持ち主が書く側になる。
- **`number_patterns` を画面から消さない。**
- 1つのフォーム(`requirements_form`)でまとめて保存する作り、`revision` による競合検出、`DraftMerge` の印は、そのまま使う。
- テストは Docker の開発コンテナで動かす(`docker compose exec web bin/rails test`)。ホストに Ruby 3.4 は入っていない。着手前の全体は 1392 runs / 0 failures。

## 作る側に委ねること

- 「＋ 科目を足す」の2段の選択(区分 → 科目)を、Stimulusでその場に出すか、選択肢を全部描いて絞り込むか。既存の `chip-adder` / `program_fields` のどちらに寄せてもよい。
- 残った決まりの箱の枠線・背景(いまの琥珀色)を続けるか、もっと静かにするか。
- 科目表の節の畳み方。節は1つの `<table>` の中の `<tbody>` で、上に `pdf_pane` のスティッキー行があるため、`<details>` でそのまま囲めない。行を `hidden` にして見出しで切り替えるか、Turbo Frame で開いたときに取りに行くか。前者が簡単だが、DOMは506行のまま残る。画面の重さが問題なら後者。
- サムネイルの大きさと、ページ数が多い便覧(`MAX_PAGES` は500)での出し方。

## 判定を変えうる変更の一覧

「判定結果を変えない」が守れているかを、ここだけ見れば確かめられるようにしておく。

| 変更 | 判定への影響 |
|---|---|
| 持ち主の欄が、隠れた決まりに書き戻す(§2) | **人が値を変えたときだけ**動く。いまは行だけ直しても判定が動かないので、これは落とし穴を埋める変更。既存データを触らなければ何も変わらない |
| `courses[].roles` に役割を足す(§3-1) | 足した役割は `one_of_paths` の関門にしか効かない。単位が増える方向には動かない |
| `DraftMerge` が読み直しで役割を消さない(§3-1) | 消えなくなるだけ。既存データは読み直さなければ変わらない |
| `group_by` の選択肢化(§3-3) | 現在値を3つめの選択肢に残すので、選び直さないかぎり変わらない |
| `GROUP_BY_NAMES` の言い換え(§8) | 学生に出る文言だけ。`graduation_golden_2024.json` に「接頭辞」の文字列は無いので、ゴールデンは動かない |
| 行の単位の欄を読むだけにする(§1-2) | 値は書き換えない。欄が無ければブラウザも送らない |

`test/fixtures/files/graduation_golden_2024.json` が動いたら、どれかが間違っている。

## 進め方

7(読むページ)と 6(科目表を畳む)は、要件表の作り直しと独立しているので、先に単独で入れてよい。
1・2(箱を隠し、持ち主が書く)が土台で、3(残る箱の書き直し)はその上に乗る。4・5・8 は最後にまとめて。
